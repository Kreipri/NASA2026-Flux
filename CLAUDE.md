# Working style for this project

**Before doing anything, read:** `CONTEXT.md` (the brief), `DECISIONS.md` (what's decided), `HANDOFF.md` (current state). Other agents may be working here too. Log decisions, save drafts to `ideas/`, and update `HANDOFF.md` before you stop.

This project is in the ideation / UI-UX drafting phase. Keep usage light, but keep the thinking sharp.

## Output format
- Default to concise text: bullets, short paragraphs, ASCII wireframes, simple flow diagrams.
- Don't build HTML pages, published artifacts, Figma files, or full code unless I ask.
- When I ask for ideas, give 3-5 distinct options, not 15 variations of one idea.

## Thinking quality (don't be dumb)
- Be opinionated: recommend one option and say why in a sentence or two.
- Name the trade-offs and the risks of each idea, not just the upsides.
- Push back if an idea has a usability, feasibility, or scope problem.
- Ask one sharp clarifying question when the answer would change the direction. Otherwise pick a sensible default and say so.
- Think about the real user: who they are, what they're trying to do, what could go wrong.

## Cost control
- Don't spawn subagents or multi-agent workflows unless I ask.
- Don't re-explain things already decided in the conversation.
- Keep replies short by default. Go deeper only when I ask or when the problem needs it.
- When a draft is ready to become something real (HTML prototype, Figma, code), ask first.
